How an escape is decided, and what this page cannot see

An escape is a test main failed after the landing and never failed before it. The baseline says whose failure it is; the rate only says how sure — {{ failure_pct }}% or more of the runs after is strong, less than that rests on few failures. Already failing before the landing makes it main's own, not the change's. Whether main is still failing the test is asked separately, over the last {{ currency_days }} days and of the escapes alone, and answers four ways: still failing, stopped failing, not run in that window at all, or not yet asked about. The last two measure nothing, so neither is counted as a recovery.

A floor, like every number here: only landings pinned from a PR title, only tests a bot runs on main in the same configuration, only the {{ window_days }} days either side. Undecided convictions are counted above, not dropped.

Legend
Escape strength — a lower bound on the failure share after the landing

The inputs are failed_after of runs_after, the pair shown beneath the figure, counted in the {{ window_days }} days after the landing.

The figure is the lower end of the 90% Wilson score interval on that ratio, not the ratio itself.

Why a bound and not the rate: the bound sinks thin evidence. 1 failure in 8 runs is 12.5% raw but 2.8% bounded, while 7 in 98 is 7.1% raw and 3.9% bounded, so the bound puts the two escapes in the right order and the raw rate does not.

It ranks escapes against each other; it is not a confidence claim. Runs are not independent trials — they cluster by machine, by neighbouring test and by load, and retries inside a step are correlated by construction.

It does not decide the strong-or-rare split shown above, which stays the raw rate against {{ failure_pct }}%, so this page never carries two definitions of strong.

Current damage — what main is doing with the test right now, as a rate

The inputs are recent_failed of recent_runs from the last currency check, over the {{ currency_days }} days ending when that check ran.

Blank means no answer, not zero: either nobody has asked yet, or main ran the test not at all in that window.

Two known limits, disclosed rather than hidden: the currency window is not clamped to the landing, so it can reach back to runs from before the change landed; and recent_runs is a floor rather than a total, because the runs query's limit of 100 applies per response group, so the oldest runs in a wide window can be dropped silently.
